## Шаг 3. Адаптировать карточки под серверный формат

Серверная карточка отличается от старой локальной карточки. Нужно проверить, что функция создания карточки использует правильные поля.

### 3.1. Ожидаемый объект карточки

```js
{
  _id: 'card-id',
  name: 'Название карточки',
  link: 'https://...',
  owner: {
    _id: 'user-id',
    name: 'Имя пользователя',
    about: 'Описание',
    avatar: 'https://...'
  },
  likes: [],
  createdAt: '2024-01-01T00:00:00.000Z'
}
```

### 3.2. Проверить функцию создания карточки

В `card.js` функция создания карточки должна:

- [ ] Принимать объект карточки с сервера.
- [ ] Использовать `cardData.name` для названия.
- [ ] Использовать `cardData.link` для картинки.
- [ ] Использовать `cardData._id` для запросов удаления и лайка.
- [ ] Использовать `cardData.owner._id` для проверки автора.
- [ ] Использовать `cardData.likes` для состояния лайка и счётчика.

### 3.3. Проверка автора карточки

Кнопка удаления должна отображаться только у карточек текущего пользователя.

Логика:

```js
const isOwner = cardData.owner._id === currentUserId;

if (!isOwner) {
  deleteButton.remove();
}
```

Нельзя просто скрывать кнопку через CSS, если она остаётся активной в DOM. Лучше удалить её из карточки.

### 3.4. Проверка лайка текущего пользователя

Нужно понять, лайкнул ли текущий пользователь карточку:

```js
const isLiked = cardData.likes.some((user) => user._id === currentUserId);
```

Если `isLiked === true`, добавить активный класс кнопке лайка.

### 3.5. Счётчик лайков

- [ ] В HTML-шаблоне карточки должен быть элемент для количества лайков.
- [ ] Например:

```html
<span class="card__like-count"></span>
```

- [ ] При создании карточки:

```js
likeCount.textContent = cardData.likes.length;
```

- [ ] После постановки или снятия лайка обновлять счётчик из ответа сервера:

```js
likeCount.textContent = updatedCard.likes.length;
```

## Шаг 4. Подключить редактирование профиля к серверу

### 4.1. Найти текущий обработчик формы профиля

Обычно он называется примерно так:

```js
function handleProfileFormSubmit(evt) {
  evt.preventDefault();
}
```

### 4.2. Заменить локальное обновление на серверное

Правильная логика:

1. Забрать значения из инпутов.
2. Показать состояние загрузки.
3. Отправить `PATCH /users/me`.
4. После успешного ответа обновить DOM.
5. Закрыть попап.
6. В `catch` вывести ошибку.
7. В `finally` вернуть обычный текст кнопки.

Пример:

```js
function handleProfileFormSubmit(evt) {
  evt.preventDefault();

  renderLoading(profileSubmitButton, true);

  setUserInfo({
    name: nameInput.value,
    about: jobInput.value,
  })
    .then((userData) => {
      renderUserInfo(userData);
      closeModal(profilePopup);
    })
    .catch((err) => {
      console.error(err);
    })
    .finally(() => {
      renderLoading(profileSubmitButton, false);
    });
}
```

Названия переменных нужно адаптировать под текущий проект.

### 6.2. Заменить локальное добавление на серверное

Правильная логика:

1. Пользователь вводит название и ссылку.
2. Отправляется `POST /cards`.
3. Сервер возвращает созданную карточку с `_id`, `owner`, `likes`.

## Шаг 8. Подключить лайки

### 8.1. Логика лайка

При клике на лайк:

1. Проверить, лайкнута ли карточка текущим пользователем.
2. Если лайкнута — отправить `DELETE /cards/likes/:cardId`.
3. Если не лайкнута — отправить `PUT /cards/likes/:cardId`.
4. Получить обновлённую карточку от сервера.
5. Обновить активный класс лайка.
6. Обновить счётчик лайков.

### 8.2. Пример обработчика

```js
function handleLikeCard(cardData, likeButton, likeCount) {
  const isLiked = likeButton.classList.contains('card__like-button_is-active');

  changeLikeCardStatus(cardData._id, isLiked)
    .then((updatedCard) => {
      likeButton.classList.toggle('card__like-button_is-active');
      likeCount.textContent = updatedCard.likes.length;
    })
    .catch((err) => {
      console.error(err);
    });
}
```

### 8.3. Более надёжный вариант

Лучше после ответа сервера заново вычислять, есть ли лайк текущего пользователя:

```js
const isLikedByCurrentUser = updatedCard.likes.some((user) => user._id === currentUserId);
likeButton.classList.toggle('card__like-button_is-active', isLikedByCurrentUser);
likeCount.textContent = updatedCard.likes.length;
```

Так интерфейс точно будет соответствовать данным сервера.

```js
function renderLoading(buttonElement, isLoading, loadingText = 'Сохранение...', defaultText = 'Сохранить') {
  if (isLoading) {
    buttonElement.textContent = loadingText;
  } else {
    buttonElement.textContent = defaultText;
  }
}
```

### 9.2. Более универсальный вариант

Чтобы не передавать каждый раз дефолтный текст вручную:

```js
function renderLoading(buttonElement, isLoading, loadingText = 'Сохранение...') {
  if (isLoading) {
    buttonElement.dataset.defaultText = buttonElement.textContent;
    buttonElement.textContent = loadingText;
  } else {
    buttonElement.textContent = buttonElement.dataset.defaultText;
  }
}
```

## Шаг 16. Настроить GitHub Actions, если деплой должен быть автоматическим

### 16.1. Проверить файл workflow

```bash
ls -la .github/workflows/deploy.yml
```

Если файла нет:

```bash
mkdir -p .github/workflows
touch .github/workflows/deploy.yml
```

### 16.2. Пример workflow

Если в курсе дан конкретный YAML — использовать его.
Если нет, можно ориентироваться на такой шаблон и адаптировать под требования задания:

```yml
name: Deploy

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Deploy to public repository
        uses: peaceiris/actions-gh-pages@v3
        with:
          personal_token: ${{ secrets.PUBLIC_PAGES_TOKEN }}
          external_repository: ${{ secrets.PUBLIC_PAGES_REPO }}
          publish_branch: ${{ secrets.PUBLIC_PAGES_BRANCH || 'main' }}
          publish_dir: ./dist
```

Если GitHub Actions ругается на выражение с `||`, заменить на фиксированное значение:

```yml
publish_branch: main
```
